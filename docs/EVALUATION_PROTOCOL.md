# VisionGuard AI 系统级验证规范

## 指标边界

队友冻结分类模型的严格OOF指标只能作为分类分支证据，不能代表VisionGuard整套系统。系统申报指标必须绑定测试清单、模型摘要、阈值、硬件、运行模式和测试日期。

0.13.0新增输入处理版本 `exif-oriented-rgb-png-v1`：先校正EXIF方向，透明像素合成白底，再将无拍摄元数据的RGB PNG送入各视觉分支。定位标签必须对应校正后显示坐标，而不是未旋转的编码像素；每条评测记录保存输入图片摘要及处理元信息。旧结果不追溯改写，也不视为新预处理下的性能复测。

评测客户端先请求健康接口建立Cookie会话，再并发提交，后续查询报告时须使用相同Cookie。CLI已自动处理；自编脚本也应遵守。`trace-and-reference-v2` 验证完整有序的工具链、必要合法引用及非空解释/复核边界；引用合规率不等于解释语义正确率，需保留解释文本供人工核验。

## 测试集要求

- 使用未参与训练、阈值选择和提示词调试的独立图片。
- 正常场景与可见火情场景均需覆盖；建议单独标记小目标、复杂光照、火焰色干扰和遮挡案例。
- 烟雾单独测试，不能把“无可见火焰”解释为“无烟雾”或“现场安全”。
- 同一视频拆帧不得随机分散到训练集和测试集，避免相邻帧泄漏。
- 记录数据来源与使用授权，不将网络未知版权图片直接作为正式申报数据集。

## 自动化测试清单

CSV采用以下字段：

```csv
image,label,task
images/fire_001.jpg,1,判断是否存在可见火情并生成复核建议
images/normal_001.jpg,0,判断是否存在可见火情并生成复核建议
```

启动服务并确认健康接口中的常驻分类器状态为 `ready`，然后运行：

```powershell
.venv\Scripts\python.exe scripts\evaluate_system.py `
  --manifest evaluation\manifest.csv `
  --output evaluation\results.json
```

输出包括分类分支Accuracy、Precision、Recall、F1及混淆计数，以及接口成功率、Agent成功率、平均/中位/P95响应时间、融合状态、风险等级、回退次数和失败明细。没有标签或分类分支不可用的样本不会被偷偷计入分类准确率分母。

## 正式报告建议

至少进行一次冷启动测试和三轮模型预热后的重复测试。正式材料分别报告分类效果、定位效果和系统效果，不把F1、mAP、接口成功率或Agent问答评价混成单一“准确率”。所有结果保留原始JSON，便于答辩追溯。
